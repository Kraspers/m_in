# Бесплатный хостинг MIN: Cloudflare Pages + Workers

Коротко:
- Да, можно подключить GitHub-репозиторий прямо в Cloudflare (как в Render).
- Frontend лучше держать в **Cloudflare Pages**.
- API (Node/Express-логика) — в **Cloudflare Workers** (часто через Hono).

## 1) Сколько пользователей выдержит бесплатно

Точного числа "пользователей" нет — лимиты считаются по запросам.

- Workers Free: **100,000 запросов в день** (сброс в 00:00 UTC).
- CPU на Free ограничен (ориентируйтесь на лёгкие обработчики).
- Pages для статики обычно бесплатный и хорошо масштабируется.

Практически:
- Если 1 активный пользователь делает ~50–200 API-запросов/день,
  то безопасный порядок на Free: примерно **500–2,000 активных пользователей/день**,
  в зависимости от чата, поллинга/реалтайма и тяжести API.

## 2) Можно ли просто указать GitHub репозиторий

Да.

В Pages:
1. Cloudflare Dashboard → Workers & Pages → Create → Pages.
2. Connect to Git → GitHub.
3. Выбери репозиторий и ветку (`main`).
4. Укажи build command/output (например `npm run build`, `dist`).
5. После каждого `git push` деплой идёт автоматически.

## 3) Как перенести с Render и подключить домен

### Шаг A. Поднять фронтенд
1. Создай Pages-проект из GitHub.
2. Проверь, что сайт открывается на `*.pages.dev`.

### Шаг B. Поднять API
1. Создай Worker.
2. Если API сейчас на Node/Express, мигрируй обработчики в Worker-совместимый формат.
3. Секреты (JWT/API keys) добавь в Settings → Variables/Secrets.

### Шаг C. Подключить домен
1. В Cloudflare добавь свой домен (если ещё не в Cloudflare DNS).
2. В Pages/Worker нажми Custom domain.
3. Cloudflare сам предложит нужные DNS-записи (`CNAME`/`A`).
4. У регистратора (или в Cloudflare DNS) обнови записи.
5. Подожди propagation (обычно минуты, иногда до 24ч).

### Шаг D. Переключение без даунтайма
1. Сначала снизь TTL DNS до 60–300 сек.
2. Проверь новый хост на поддомене (например `new.min.ru`).
3. Переключи основной домен.
4. Оставь Render на 24–48ч как fallback.

## 4) Важный момент про "много пользователей"

Если у тебя реально большой мессенджер, полностью бесплатный режим почти наверняка упрётся в лимиты Workers.
Минимально болезненный путь:
- фронт оставить на бесплатных Pages,
- API оптимизировать (кэш, батчинг, rate-limit),
- при росте перейти на недорогой paid для API.


## 5) Куда нажимать в твоём окне Cloudflare (как на скриншоте)

1. Нажми **Create application** (синяя кнопка справа сверху).
2. Выбери **Workers** (не Pages, потому что это backend/API).
3. Нажми **Start with Hello World**.
4. Назови сервис: `min-api`.
5. После создания открой Worker и нажми **Edit code**.
6. Вставь код из `worker-api/src/index.js` и нажми **Deploy**.
7. Открой `https://<твой-worker>.workers.dev/health` — должен быть JSON `{"ok":true,...}`.
8. Далее в Worker зайди в **Settings → Variables and Secrets** и добавь секреты.
9. Затем **Settings → Triggers / Domains & Routes → Add Custom Domain** и укажи `api.твойдомен`.
